Business Scenario: Order Management System

We need a backend system to manage customer orders for an online store.

Entities involved:
- Customer: has a name, email, phone number, and a shipping address.
- Product: has a name, description, price, and stock quantity.
- Order: placed by one customer, contains one or more order items, has a
  status (PLACED, CONFIRMED, SHIPPED, DELIVERED, CANCELLED), and an order
  date.
- OrderItem: references a product, has a quantity, and the price at the
  time of order.

Main flows:
1. A customer places an order containing one or more products. The system
   checks stock availability for each product before confirming the order.
   If any product is out of stock, the order is rejected with a clear
   error message.
2. Once an order is placed successfully, stock quantity for each ordered
   product is reduced accordingly.
3. A customer can view the status and details of their past orders.
4. An admin can update an order's status (e.g. mark it as shipped).
5. A customer can cancel an order only while it is still in PLACED status;
   cancelling restores the stock quantity for each item.

Business rules:
- Email must be unique per customer.
- Order quantity for any item must be at least 1.
- Product price must be greater than 0.
- Only an authenticated user can place an order for themselves.
- Only an admin role can update order status or view all customers' orders.
- All endpoints must support pagination for list operations (e.g. listing
  orders, listing products).
